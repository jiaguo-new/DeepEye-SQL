# DeepEye-SQL: provenance, adaptations, and what each artifact actually is

Upstream: `HKUSTDial/DeepEye-SQL` (MIT), commit `252ab45a7adf9f88fb93d1ff27ca019d20f0449a`.
Upstream publishes **no code redistribution here**: this repo contains none of their source.

Two distinct things, previously conflated in our wording (audit finding F3 — accepted):

1. **A locally executed adapted pipeline** (Nov-2026 runs `bird-dev-qwen38-adapt*`,
   `bird-blind221-deepeye12_*`, `bird-coverage8_*`): 6 plumbing-only adaptations
   (LLM→gateway `qwen3.8-27b`, embedding→gateway `qwen3-embedding:8b`, cuda→cpu,
   n>1 split into 1-sample requests, one-line extractor timeout patch,
   pyproject/uv.lock). Its output is **Pool D candidate draws** (12 sampled SQLs per
   question + observable execution-cluster evidence, `data/DE12_POOL.goldfree.json`).
   Token cost is in the real ledger (124,416,106 prompt / 51,528,651 completion).
   Algorithm untouched.

2. **The upstream-published final predictions file** `results/bird-dev/qwen3.6-27b.json`
   (SHA `0d073da4…`, verified byte-identical to upstream git blob @252ab45a on
   2026-11-06). This is **their released artifact** (generated by upstream with their
   own model), NOT a product of our local rerun. Selector rules D/E/F may switch the
   final answer to a member of this file's corroborated clusters ("rule B").

Scoring facts, all fresh official-evaluator runs against current publisher gold
(dev.zip `cdd6d19f…`, downloaded 2026-11-06, byte-identical to the 2026-11-02 copy):
* upstream published file rescored: **1141/1534 = 74.38%** (79.89/68.10/59.31), 30 s.
  The upstream paper reports 74.5; our earlier "1143 = 74.51% local rescore" was a
  240 s-budget run — both are rescorings of *their* artifact, never "our run".
* our shipped system with all of the above: 1146 = 74.71% (SELECTOR_V16_SPEC.md).

The `complete_pipeline_deployed: false` note in the October baseline decision is
accurate *for October*: the from-scratch adapted DeepEye run (with its own final
selector) was executed later (November), and in any case the shipped chain consumes
only (1) its candidate pool and (2) the upstream-published final file — not a local
rerun of their final selector.
