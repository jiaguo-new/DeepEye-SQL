### 4.1 第二轮迭代（2026-11-06 晚，负结果地图）

在冻结系统上系统探索了 6 条剩余提升路径，**全部为负结果或不可行**；
系统维持 1086/70.80% 不变。记录如下，避免重走：

| 路径 | 依据/设计 | 结果 |
|---|---|---|
| R1 扩池引入新家族 | 全盘 47 个语料谱系鉴定 | **不可行**：剩余语料全部是 qwen/deepseek/ck800 衍生（qid-0 SQL 与现有臂重合），无独立谱系可加；加入会造成同谱系伪共识 |
| R2 题型形状规则（TRAIN 校准） | 3,844 条 TRAIN gold 执行：HOW_MANY 单格 90.1%/单行 95.6% | **负**：SHAPE-GATE k∈{2,3} 得 1079/1081（-5/-3）；SHAPE-VETO 零变化（162 次覆写中无形状冲突案例） |
| R3 证据字面量链接 | 题面/evidence 引号串与数字在候选 SQL 中的覆盖度 | **无信号**：平局案例 739/741 覆盖度完全相同（所有候选都过滤同样的题面字面量） |
| R4 COUNT 粒度修正 | TRAIN 先验：HOW_MANY gold 中 COUNT(DISTINCT) 仅 7.5%（PLAIN 58.9%）——仓库自带 count_distinct_selector 的 80% 前提不成立 | 精确规则（输出 SQL 为 DISTINCT 粒度时替换为 de-DISTINCT 变换）：43 题触发，**净 -6**（rescue 6 / damage 12）。早先宽松口径的 +9 系测量不严所致，已修正 |
| R5 TRAIN 拟合选择器 | 前代未做方向 | **不可行**：本地无 TRAIN 候选池（仅 130 条 fixture）；TRAIN DB 覆盖 4,185/9,428 题但无对应候选 |
| R6 覆写质量门（alt 需 ≥N 个强家族支持） | 家族强度集为 dev 衍生 | min_top∈{1,2,3} → +0/-1/+3，非单调噪声模式，**判为过拟合，不采纳** |
| 附 | de-DISTINCT 变换对生成墙的击穿 | 12/204 墙题可被变换救回（oracle 1327→1339），但精确切换规则净负（见 R4），无路径让选择器可靠选中它们 |

结论：执行证据选择器在此候选池上已达证据上限；剩余增益需要生成侧
（模型网关重生成低共识题）或语义判断（前代已证 LLM judge 净负）。

## 5. 饱和度诊断（为什么停在这里）

* 官方口径 448 题错误。缓存口径 452 题错误中：
  * **207 题：47,692 候选池内无任何正确 SQL**（生成墙，选择器无能为力）；
  * 68 题：正确簇与锚点簇家族数相同（家族计数证据的判决极限）；
  * 40 题：锚点正确但被覆写（融合代价，对应 61 次 rescue）。
* 继续提升需要：更强的生成（需要模型网关，本机不可用）或语义判断
  （前代已实测 LLM judge 全量外推净负，NO-GO）。
* 执行证据选择器在此池上的规则族已饱和：网格 8 种变体全部落在 1080-1084。
